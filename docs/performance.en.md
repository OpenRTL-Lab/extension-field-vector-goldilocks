# Performance

[简体中文](performance.md)

This document separately reports task latency, repeated-task throughput, and useful arithmetic utilization. Under ideal interfaces, long-vector multiplication approaches one extension element per cycle, with 99.95% useful occupancy on all three base-field multiplication pipelines. Every cycle count is reproducible through the published simulation chain.

L counts extension elements per task, each represented by two base-field coefficients. ADD/SUB/MUL/SQUARE/INV/FMA return L elements; DOT returns one reduced element. II is element initiation interval. The 16 inverse contexts interleave elements of one task through base-field multiplier 0, not 16 tasks or 16 multipliers.

## Definitions and measurement

The representative configuration has maximum length 65,536, one element datapath, and 16 inverse contexts. Measurement uses ideal native interfaces without external memory bandwidth/latency limits: the environment offers available data immediately and keeps output/completion ready. The product's finite queues and context-admission logic remain active.

For task j, A is the task handshake cycle, F the first output handshake, O the last output handshake, and C the completion handshake. Task latency is C−A, while final-result latency is O−A; tasks with no output have no result latency. These are circuit cycles, not simulation-host wall-clock time.

For K repeated tasks of one mode and length, use T=C_last−C_first to measure `(K−1)/T` tasks per cycle and `L×(K−1)/T` input elements per cycle. DOT output-element throughput equals task throughput. Batch throughput is measured directly, not inferred from a single task's latency.

Useful issue utilization is valid multiplier issue cycles divided by C−A. Useful occupancy is the union of the 14-cycle arithmetic-stage intervals generated by those issues, divided by C−A. Busy plus idle cycles equals the task window. Register toggling without valid work does not count. The entry register contributes to the separate 15-cycle feedback latency and is not double-counted as arithmetic occupancy.

## Long-task latency

| Operation and input | Input elements | Task latency, cycles | Final-result latency, cycles |
| --- | ---: | ---: | ---: |
| ADD / SUB / MUL / SQUARE / FMA | 65,536 | 65,579 | 65,578 |
| DOT | 65,536 | 65,596 | 65,595 |
| INV, all nonzero | 4,096 | 552,987 | 552,986 |
| INV, all zero | 65,536 | 131,076 | 131,075 |

The ordinary element datapath has II=1. The all-zero INV case covers the zero-handling boundary, not nonzero-inversion performance. The measured long nonzero INV task contains 4,096 elements.

## Repeated-task throughput

| Mode | Length per task | Batch tasks | Task latency, cycles | Completion interval, cycles | Tasks/cycle | Input elements/cycle |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| ADD / SUB / MUL / SQUARE / FMA | 32 | 64 each | 75 | 76 | 0.0131579 | 0.421053 |
| DOT | 32 | 64 | 92 | 93 | 0.0107527 | 0.344086 |
| INV, all nonzero | 256 | 16 | 34,587 | 34,588 | 0.0000289118 | 0.00740141 |

The product supports one in-flight task with no task overlap. Completion intervals include task release and readmission. Latency and throughput are independently measured; continuous element-pipeline reuse does not imply task-level parallelism.

## Arithmetic utilization

| Workload | Unit | Useful issue cycles | Occupied cycles | Idle cycles | Issue utilization | Occupancy |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| MUL / SQUARE / FMA, L=65,536 | Each of three base-field multipliers | 65,536 | 65,549 | 30 | 99.9344% | 99.9543% |
| DOT, L=65,536 | Each of three base-field multipliers | 65,536 | 65,549 | 47 | 99.9085% | 99.9283% |
| INV, 4,096 nonzero elements | Base-field multiplier 0 | 536,576 | 551,392 | 1,595 | 97.0323% | 99.7116% |
| INV, same case | Each of base-field multipliers 1 and 2 | 0 | 0 | 552,987 | 0% | 0% |

ADD/SUB and all-zero INV issue no useful multiplications. Ordinary multiplication issues every cycle in its uninterrupted compute segment; the task-window values include pipeline filling/draining. The tool also reports 17 named arithmetic groups covering pre-addition, post-processing, FMA, bypasses, DOT accumulation/three merge levels, and INV norm/negation. Per-task records include logical field-operation counts, busy/idle cycles, and task-window/compute-segment utilization. Full values appear in `performance.json`, separating parallel field-operation counts from cycle counts.

## Cycle-to-time conversion

At clock frequency f, time equals `cycles/f` and throughput equals `tasks_per_clock×f`. Using the 500 MHz setup-gated parameter, a 65,536-element MUL takes 131.158 µs; repeated 32-element MUL reaches 6.57895 million tasks/s and 210.526 million input elements/s. These are frequency conversions of measured cycles, not additional physical measurements. Conditions are in [Synthesis summary](synthesis-summary.en.md).

## Reproducing the measurements

The full set contains 444 tasks and 411,963 result records, covering seven operations, length boundaries, bad frames, zero inversion, and repeated batches. Regenerated and bundled products each run ideal, backpressure, three reset-recovery, and negative-reference tests. The negative test corrupts one expected value and must detect exactly one error with a nonzero exit. A 32-context configuration receives a separate functional test and is not presented as the bundled 16-context result.

Run the full-performance command in [Reproduction](reproduction.en.md), then inspect `results.json` and both `performance.json` files. The tool checks exact equality of the two products' measurements. Clock markers and valid counters come from the environment, not statistics ports in the product.
